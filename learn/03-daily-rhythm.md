# The daily rhythm

Five runs make a weekday. Times below are examples; set your own in the company clock (`07-company-clock.md`).

## Numbers (early morning, organizers and owners only)

Yesterday's numbers from every source on the data map, checked before they're written, with a chart against a baseline. A number that fails a check is left blank with the reason. Writes to the owner's storage and, if you want, a copy to the shared folder for people who don't run their own. Sends nothing to anyone else.

## Agendas (before the first meeting, meeting organizers only)

For each of today's meetings the person organizes: one shared agenda and one set of private notes. The shared agenda folds in the "what I'd add" files teammates' runs left in the shared folder, and credits each contributor by name. Two-person meetings never go in the shared folder (see `08-privacy-zones.md`).

## Morning brief (start of the workday, everyone)

Everything since the last debrief: new mail, chat, transcripts, task changes. It reconciles the person's open loops, lists what they owe and what they're owed, links today's agendas, and ends with a coverage line that names every source it read and every source that failed. It goes to the person by email, with a link to a private page version that adds charts.

## Midday refresh (by hand, anytime)

The whole day rebuilt as of that minute. Read only: it records nothing and closes nothing. Useful before a meeting or after a long call.

## Evening debrief (end of the workday, everyone)

Closes loops that have evidence, drafts the messages the person owes (oldest first, a fixed cap per run), drafts nudges for things owed to them that are past due, writes "what I'd add" files for tomorrow's meetings they don't run, and appends new facts to their working notes. On the last workday of the week it carries one list of stale items for the person to keep, close or drop.

## Send check (twice a day)

Runs the receipts gate on every open draft and emails the owner only when something needs a fix or is on hold. See `04-receipts.md`.

## Weekly team update (once a week)

One run that turns the week's task-board movement into a status update for the team meeting. This is the one run that may post for a person, and only for its owner, who edits it before the meeting.

## What every run does, without exception

- First line: append "started" with the time, the rules versions it read and its prompt version to the owner's runs log.
- Last line: append "finished" with coverage and links to its outputs.
- Times come from a clock tool or the date command, never from Claude's own sense of time.
- Email only the owner. Anything for anyone else is a draft.
